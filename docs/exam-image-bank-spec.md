# Спецификация банка заданий с изображениями

## Цель

Импортировать задания из предоставленных PDF-сборников в отдельную версию учебного каталога, сохранив формулы, таблицы и чертежи в виде изображений. В пробнике показывать одно задание за раз, поддержать навигацию по номерам и увеличение картинки.

## Исходные материалы

- банк база v10.pdf — ЕГЭ по математике, базовый уровень.
- банк-проф v6.pdf — ЕГЭ по математике, профильный уровень.
- Пользователь подтвердил наличие разрешения составителя на извлечение заданий и размещение их в сервисе.

## Архитектура

1. Импортёр читает PDF и использует именованные ссылки `task::ID` и `ans::ID` как идентификаторы заданий и ключей ответов. Для каждого задания границы изображения определяются по координатам соседних ссылок на странице, а задания на нескольких страницах делятся на фрагменты.
2. Исходные векторные формулы, таблицы и чертежи рендерятся напрямую в WebP; OCR не используется. Изображение остаётся точным снимком задания, а текстовое условие и краткие ответы сохраняются в каталоге отдельно.
3. Изображения загружаются в существующее MinIO-хранилище по стабильным ключам `curriculum/assets/mathstart/<track>/<pdf-sha256>/<task-id>/<segment>.webp`.
4. В CurriculumTask.metadata сохраняются imageKeys, examQuestionNumber, examPart, sourcePageStart, sourcePageEnd и версия импортёра. Для устаревшего профильного вопроса 21 указывается `isLegacy=true`; его задания хранятся в каталоге, но не попадают в обычный вариант.
5. При создании MockExam данные изображения копируются в снимок MockExamItem, чтобы уже созданный пробник не менялся после обновления каталога.
6. API отдаёт авторизованному участнику URL или поток изображения только для задания из доступного пробника. Текущие публичные URL хранилища не используются.
7. Студенческий экран показывает одно задание, номера навигации, адаптивную ширину и увеличение изображения; текстовое условие остаётся запасным вариантом для старых или текстовых заданий.

## Совместимость и миграция

- Старые релизы, задания и завершённые пробники остаются в БД. При активации нового банка предыдущий активный релиз того же трека выключается, но не удаляется и может быть активирован обратно.
- Импорт создаёт отдельные релизы для EGE_BASE и EGE_PROFILE с источником imported.
- Новые релизы `2026.1-f1c4f7321614` (базовый) и `2026.1-1e0b2ddcb911` (профильный) активированы после проверки импорта.
- Повторный импорт идемпотентен по хэшу PDF, типу экзамена и версии импортёра.
- Базовый банк содержит 7 616 корректных пар ссылок на условие и ответ. Профильный — 1 869 корректных заданий и ключей; одно ошибочное назначение `task::5.8.1` на обложку исключается, а 127 заданий вопроса 21 помечаются устаревшими.
- Вариант базового уровня содержит по одному случайному заданию из 21 номера; профильный — по одному из 20 актуальных номеров. Все 437 заданий с развёрнутым ответом оставлены без автоматического ключа и передаются преподавателю на ручную оценку.
- Для ручной оценки в кабинете преподавателя добавлена очередь «Проверка пробников». При смене активной версии профиль ученика автоматически привязывается к новому каталогу.

## Проверки качества

- Проверить несколько задач с формулами, таблицами и чертежами из каждого PDF.
- Проверить задачи, переходящие через границу страницы.
- Проверить, что вариант содержит не более одного случайного аналога на номер вопроса и показывает вопросы в экзаменационном порядке.
- Проверить, что изображения читаются на телефоне и увеличиваются без обрезания.
- Проверить создание пробника, сохранение ответов, завершение и повторное открытие.
- Проверить очередь преподавателя и ручную оценку развёрнутых ответов.
- Проверить, что старые пробники без imageKeys продолжают отображаться через текстовый рендер.

## Ограничения

- Изображения выдаются только после проверки прав доступа к пробнику.
- Содержимое PDF не попадает во frontend-сборку и не хранится в Git.
- При сбое MinIO интерфейс показывает текстовое условие и понятное сообщение, не ломая прохождение пробника.
